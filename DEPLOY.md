# Публикация сайта

Главное, что стоит понять до выбора хостинга: **серверу тут нечего делать**. Сайт
собирается в 439 обычных файлов, среди них 49 готовых html-страниц, `sitemap.xml`
и `robots.txt`. Ни базы, ни Node-процесса на проде нет. Раздать это может что угодно:
CDN, статический хостинг, nginx на самом дешёвом VPS

```bash
npm ci
npm run build      # собирает статику в папку out
```

Дальше папка `out` целиком уезжает на хостинг. Всё

Локально посмотреть собранное: `npm start`, откроется на 3000. Проверить
ограничения проекта на запущенном: `npm run check`

## 1. Репозиторий на GitHub

Нужен в любом случае: это исходник проекта и точка, из которой деплоят все площадки

Репозиторий уже инициализирован, первый коммит сделан. Осталось создать пустой
репозиторий на GitHub и запушить:

```bash
git remote add origin git@github.com:<логин>/servercalc.git
git push -u origin main
```

Приватный подойдёт: и Timeweb, и Vercel умеют деплоить из приватных репозиториев
после подключения через OAuth

## 2. Где раздавать сайт

Сравнение по тому, что важно именно этому проекту: аудитория российская,
трафик планируется органический из Яндекса

| | Доступность из РФ | Цена | Приватный репозиторий | Что делать руками |
|---|---|---|---|---|
| **Timeweb Cloud, статическое приложение** | полная, серверы в РФ | от нескольких сотен рублей | да, бесплатно | ничего, деплой по push |
| **VPS с nginx** | полная, серверы в РФ | 300-600 ₽/мес | да | настроить nginx и сертификат один раз |
| **GitHub Pages** | с мая 2026 деградирует | GitHub Pro 4 $/мес для приватного репо | только на Pro | ничего, деплой по push |
| **Vercel** | часть аудитории не открывает | Pro 20 $/мес, Hobby запрещён | да | ничего |

Vercel настроен и готов, подробности и как проверить доступность в разделе 5.
Про GitHub Pages в разделе 5.1

## 3. Рекомендуемый путь: Timeweb Cloud, статическое приложение

1. Панель Timeweb Cloud, раздел **Приложения**, кнопка создать
2. Подключить GitHub, выбрать репозиторий `servercalc`, ветку `main`
3. Тип приложения: **фронтенд**, фреймворк Next.js
4. **SSR не включать**: сайт статический, серверный режим тут только дороже.
   Важно, что после деплоя SSR уже не отключить, так что выбирать сразу
5. Команда сборки `npm run build`, каталог с результатом `out`
6. Привязать домен, сертификат Let's Encrypt выпускается там же в панели
7. Каждый `git push` в `main` пересобирает и выкатывает сайт

Отдельный плюс: мы становимся клиентом провайдера, который сами же сравниваем
в каталоге. Это готовый материал для раздела обзоров и честный ответ на вопрос
«а сами вы где хоститесь»

## 4. Запасной путь: VPS с nginx

Подходит, если нужен полный контроль или уже есть сервер

```bash
# на сервере
sudo apt install -y nginx
sudo mkdir -p /var/www/servercalc
```

Сборка делается локально или в CI, дальше папка уезжает на сервер:

```bash
npm run build
rsync -av --delete out/ user@server:/var/www/servercalc/
```

Конфиг nginx:

```nginx
server {
    listen 80;
    server_name servercalc.ru www.servercalc.ru;
    root /var/www/servercalc;
    index index.html;

    # чистые адреса: /catalog отдаётся из catalog.html или catalog/index.html
    location / {
        try_files $uri $uri.html $uri/ /404.html;
    }

    # хеши в именах, можно кэшировать надолго
    location /_next/static/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    location = /404.html {
        internal;
    }

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
}
```

Сертификат: `sudo certbot --nginx -d servercalc.ru -d www.servercalc.ru`

Пересборка после парсера цен вешается на тот же cron, что и сам парсер

## 5. Vercel из того же репозитория

Технически работает и настроено: в корне лежит `vercel.json`, который говорит
собирать через `npm run build` и раздавать папку `out` как статику

1. vercel.com, Add New Project, подключить GitHub, выбрать `servercalc`
2. Настройки Vercel подхватит из `vercel.json`, менять ничего не надо
3. Домен привязывается в Settings → Domains

**Два условия, которые надо знать до того, как вести туда боевой домен**

*Первое, про деньги.* Бесплатный план Hobby прямо запрещает коммерческое
использование, и в списке примеров отдельной строкой стоит «партнёрские ссылки
как основное назначение сайта». Это дословно наш случай, значит нужен Pro
за 20 долларов в месяц. Для статики это в несколько раз дороже российского
хостинга, но само по себе не блокер

*Второе, про доступность, и вот оно важное.* Есть сообщения, что сайты на Vercel
не открываются у части российских пользователей, особенно с мобильного интернета:
IP-адреса площадки фильтруются на уровне провайдеров. Проект живёт на органике
из Яндекса, поэтому недоступность бьёт дважды: посетитель уходит, а робот
поисковика получает таймауты при обходе и хуже индексирует сайт

**Как проверить за две минуты, не полагаясь на чужие слова.** Возьмите телефон
с российской симкой, выключите wifi и откройте любой известный сайт на Vercel.
Если открывается стабильно у вас и у пары знакомых с разными операторами,
вопрос снят. Если нет, боевой домен туда вести нельзя

**Разумный компромисс.** Обе площадки деплоятся из одного репозитория, это ничего
не стоит. Заведите проект и на Timeweb, и на Vercel, неделю посмотрите на оба,
а домен направьте туда, что окажется надёжнее. Vercel в любом случае удобен под
превью веток: черновики смотрите вы, а не аудитория

## 5.1. Про GitHub Pages

Тоже вариант, но два ограничения. С 5 мая 2026 доступ к GitHub из России
деградирует: не блокировка, а фильтрация по SNI на ТСПУ, доля неудачных
соединений выросла с 4% до 16%. И на бесплатном плане Pages работает только
из публичного репозитория, для приватного нужен GitHub Pro

Workflow для Pages лежит в `.github/workflows/pages.yml`, он выключен и ждёт
ветку `pages`, если понадобится стенд

## 6. Что сделать до первой публикации

1. Купить домен и вписать его в `data/site.json`, поля `domain` и `url`
2. Заполнить там же `operator` и `contactEmail`, они подставятся в политику
   конфиденциальности и на страницу «О проекте». Без них модерация Директа
   отклонит объявления
3. Подать уведомление оператора персональных данных в Роскомнадзор,
   бесплатно через pd.rkn.gov.ru
4. Завести цели в кабинете Метрики 111249191: `provider_click`, `calc_result`,
   `catalog_filter`, `cookie_accept`
5. Добавить сайт в Яндекс Вебмастер и отправить `sitemap.xml`
6. Заменить демонстрационные цены и переключить `meta.dataStatus` в
   `data/taxonomy.json` с `demo` на `live`
