# Публикации ServerCalc: как это устроено и как выпускать

Материал = один markdown-файл в `content/news`. Никакой админки: положили файл,
пересобрали, опубликовали. Файлы `README.md` и файлы с `_` в начале имени
публикациями не считаются.

## Фронтматтер

```
---
title: "Заголовок. Двоеточия внутри — только в кавычках"
date: 2026-08-06
updated: 2026-08-06        # необязательно
rubric: novosti | obzory | ceny
provider: timeweb          # необязательно: включает кнопку перехода к провайдеру
description: "Одно предложение для сниппета выдачи, до 160 символов"
author: Редакция ServerCalc
---
```

Поле `provider` — slug из `data/providers.json`. Если оно задано, внизу материала
автоматически появляется блок «Провайдер из этого материала» с партнёрской кнопкой:
метка собирается как `utm_campaign=news_<провайдер>`, клик считается целью `provider_click`.

## Редакционная политика

Тон дороже скорости. Мы пишем для людей, которые считают деньги, поэтому:

1. **Ничего не выдумывать.** Каждый факт из реально открытого первоисточника.
   Дат, цифр и названий «по памяти» не существует.
2. **Каждый материал делает работу.** Три рабочих жанра:
   - *сравнение* — цифры двух и более провайдеров рядом, вывод в рублях;
   - *акция с разбором* — не «скидка 30%», а сколько это в деньгах на реальном
     тарифе и что будет с ценой после первого срока (связка со страницей /akcii);
   - *разбор события* — что случилось и что это меняет для того, кто выбирает сервер.
3. **SEO без мусора.** Заголовок содержит запрос, по которому материал должен
   находиться; description — законченное предложение; в тексте есть внутренние
   ссылки на каталог, подбор или страницу провайдера. Ключ не повторяется
   в каждом абзаце: один запрос — один материал.
4. **Никаких превосходных степеней без критерия** (ст. 5 ФЗ «О рекламе») и ничего
   про VPN и обход блокировок.
5. **Разделов «Источники» на странице нет** — откуда данные, говорим одной строкой
   прозой в конце. Внешние ссылки в тексте открываются в новой вкладке
   с rel="nofollow noopener" автоматически.
6. **Не повторять вышедшее**: перед публикацией проверить slug в этой папке.

## Еженедельный цикл

1. Собрать проверяемые события за неделю: прайсы и акции провайдеров из каталога,
   регуляторика (реестр РКН, идентификация, НДС), рынок IaaS. Мало фактуры —
   выпустить меньше, хоть один материал.
2. Написать файл по правилам выше, дата — день публикации.
3. `npm run build` и `node scripts/check.mjs` — проверка обязательна.
4. Публикация через стейджинг и `.publish-request` (метод MakeBiz).

## Метод ВИДНО: шаблон каждого материала (с 23.10.2026)

Применять ко всем новостям, гайдам и посадочным без отдельной команды.

- **Абзац-ответ сразу под H1** (лид): 2-3 предложения с цифрой: цена «от», число тарифов, дата проверки цен. Читатель и нейросеть получают ответ, не листая
- **Таблица в каждом гайде и посадочной** на данных сайта: тарифы, сравнение провайдеров, требования к RAM/CPU. Только тарифы и цены, которые сайт и так показывает, с датой проверки
- **5-7 утвердительных H2** («2 ГБ памяти хватает боту на 5 000 пользователей», а не «Сколько памяти нужно?»). Примеры условные («проект на 3 сайта WordPress», «бот на 5 000 пользователей»), выдуманных историй и клиентов нет
- **Перелинковка:** 3-7 ссылок на посадочные (дешёвый VPS, VPS под задачу, гео-страницы, калькулятор) и 3-5 на соседние гайды. Внутренние ссылки БЕЗ UTM
- **CTA посередине** под задачу текста: ссылка на калькулятор или на посадочную под эту задачу (внутренняя, без UTM), либо кнопка провайдера из каталога сайта. Второй CTA в конце
- **FAQ 4-6 вопросов** с разметкой FAQPage и блок «Читайте также» на 3 ссылки
- **Разметка:** Article/NewsArticle + BreadcrumbList (ставит генератор) + FAQPage; у посадочных ItemList тарифов
- **Объём:** гайд 1 000-1 300 слов, новость 350-700, посадочная 600-1 000 слов плюс таблица
- **Дата проверки цен** в первой строке посадочных (уже есть, не убирать)

**Пропорция выпусков:** посадочные 50% (волны по средам), гайды 30%, новости 20%. Новость только при свежем проверяемом поводе за 7 дней и с денежным выводом для читателя, каждая новость ссылается на 1-2 посадочные и калькулятор. Гайды под вопросы, которые люди задают нейросетям («сколько RAM нужно для …», «VPS или облако для …», «как выбрать VPS для 1С»), каждый ведёт на посадочную. Если топ-10 выдачи по теме целиком занят агрегаторами с большой историей, берём узкий хвост

## UTM и переходы к провайдерам

- Внутренние ссылки по сайту никогда не размечаем UTM: иначе Метрика и GA4 теряют настоящий источник визита
- Ссылки на провайдера только через механизм сайта (ниже), реф-ссылку не переписываем и не собираем руками из головы. Реф-параметры (Timeweb `i=143675` и остальные) не трогаем
- Схема меток на переходах к провайдерам уже работает на сайте и в кабинетах партнёров, её не меняем: `utm_source=<сайт>`, `utm_medium=<язык>`, `utm_campaign=<страница или слаг материала>`, `utm_content=<провайдер>`
- **is*hosting (ishosting.io/affiliate/…) уходит без UTM:** у него флаг noUtm, лишние параметры ломают партнёрку. Только событие перехода
- Событие перехода `provider_click` с 23.10 несёт `page` (адрес страницы, откуда ушли), `provider` и `place`. По нему замер считает, какая страница приводит переходы
- Ссылки на наши сайты: podborvps.ru ↔ servercalc.ru и servercalc.com ↔ serverselection.online с метками `utm_source=<этот сайт>&utm_medium=<news|guide|landing>&utm_campaign=<слаг материала>&utm_content=<cta_mid|table|faq|end>`. На makebiz.life ссылки не ставим без задачи. Посты в Telegram и соцсетях: `utm_source=telegram&utm_medium=social&utm_campaign=<слаг>`

### Как это сделать в материале ServerCalc.ru (content/news, markdown)

- Таблица: обычная markdown-таблица (рендер marked понимает GFM), данные только из `data/plans.json` с `verifiedAt`, рубли как на сайте
- CTA посередине: ссылка на `/vps-dlya/<задача>/`, `/vps/<страна>/` или калькулятор `/kalkulyator/`, без UTM
- Кнопка провайдера: только через `provider:` во фронтматтере, компонент OutLink сам ставит метки и событие `provider_click` (`page` на этом сайте пока не передаётся: код ServerCalc.ru меняет только публикатор с Мака). Вручную реф-ссылки в текст не вставлять
- FAQ: раздел `## Частые вопросы` с вопросами `### …?` и в самом конце файла один блок `<script type="application/ld+json">` FAQPage с теми же вопросами
- «Читайте также»: 3 ссылки на соседние материалы и посадочные в конце текста
- Блок «Что это значит для бюджета» с расчётом в рублях остаётся обязательным

### GEO

- `/llms.txt` и `/llms-full.txt` собираются из данных при каждой сборке (`app/llms.txt`, `app/llms-full.txt`), отдельно пересобирать не нужно
- IndexNow на каждый новый адрес: `https://api.indexnow.org/indexnow?url=<адрес>&key=f4c071a35fed0f6f7e7ed4ab4f43ff59` (ключ лежит в `public/`)
- robots.txt (`app/robots.txt/route.js`) открывает ИИ-ботов, но это существующий код: менять только вместе со стейджингом на Маке
- Существующие файлы кода не трогать, только новые файлы и `content/`
