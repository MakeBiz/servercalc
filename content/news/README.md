# Публикации ServerCalc: как это устроено и как выпускать

Материал = один markdown-файл в `content/news`. Никакой админки: положили файл,
пересобрали, опубликовали. Файлы `README.md` и файлы с `_` в начале имени
публикациями не считаются.

## Фронтматтер

```
---
title: "Заголовок. Двоеточия внутри — только в кавычках"
date: 2026-08-06
updated: 2026-08-06        # необязательно
rubric: novosti | obzory | ceny
provider: timeweb          # необязательно: включает кнопку перехода к провайдеру
description: "Одно предложение для сниппета выдачи, до 160 символов"
author: Редакция ServerCalc
---
```

Поле `provider` — slug из `data/providers.json`. Если оно задано, внизу материала
автоматически появляется блок «Провайдер из этого материала» с партнёрской кнопкой:
метка собирается как `utm_campaign=news_<провайдер>`, клик считается целью `provider_click`.

## Редакционная политика

Тон дороже скорости. Мы пишем для людей, которые считают деньги, поэтому:

1. **Ничего не выдумывать.** Каждый факт из реально открытого первоисточника.
   Дат, цифр и названий «по памяти» не существует.
2. **Каждый материал делает работу.** Три рабочих жанра:
   - *сравнение* — цифры двух и более провайдеров рядом, вывод в рублях;
   - *акция с разбором* — не «скидка 30%», а сколько это в деньгах на реальном
     тарифе и что будет с ценой после первого срока (связка со страницей /akcii);
   - *разбор события* — что случилось и что это меняет для того, кто выбирает сервер.
3. **SEO без мусора.** Заголовок содержит запрос, по которому материал должен
   находиться; description — законченное предложение; в тексте есть внутренние
   ссылки на каталог, подбор или страницу провайдера. Ключ не повторяется
   в каждом абзаце: один запрос — один материал.
4. **Никаких превосходных степеней без критерия** (ст. 5 ФЗ «О рекламе») и ничего
   про VPN и обход блокировок.
5. **Разделов «Источники» на странице нет** — откуда данные, говорим одной строкой
   прозой в конце. Внешние ссылки в тексте открываются в новой вкладке
   с rel="nofollow noopener" автоматически.
6. **Не повторять вышедшее**: перед публикацией проверить slug в этой папке.

## Еженедельный цикл

1. Собрать проверяемые события за неделю: прайсы и акции провайдеров из каталога,
   регуляторика (реестр РКН, идентификация, НДС), рынок IaaS. Мало фактуры —
   выпустить меньше, хоть один материал.
2. Написать файл по правилам выше, дата — день публикации.
3. `npm run build` и `node scripts/check.mjs` — проверка обязательна.
4. Публикация через стейджинг и `.publish-request` (метод MakeBiz).
